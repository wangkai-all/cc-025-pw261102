# 多触点归因分析

导入触点、身份绑定、成交与退款数据,在**首次触达 / 末次非直接触达 / 线性分摊**三种归因口径之间切换,并支持调整回看天数。渠道汇总、成交路径与分摊明细均可在页面上逐笔展开。

## 运行

```bash
# 后端(FastAPI + DuckDB,内存库)
cd backend
../.venv/bin/python -m uvicorn app.main:app --port 8000
# 打开 http://localhost:8000 (已内置前端构建产物),点击"载入演示数据"

# 前端开发模式(可选,代理到 8000)
cd frontend && npm run dev

# 规则测试
cd backend && ../.venv/bin/python -m pytest tests/ -q
```

## 归因规则

- 只使用**成交前(含同一时刻)且落在回看窗口内**的触点;触点按 `(时间, 触点编号)` 排序,同一时刻按编号升序。
- 身份绑定只使用**成交时已经建立**的关系(`bound_at <= 成交时间`),成交后的登录不会把过去的匿名访问串到该笔成交上(对之后发生的成交则生效)。
- 末次非直接:优先窗口内最后一个非直接渠道;没有非直接时回退到最后一个直接访问;完全没有触点归入**未知来源**。
- 同一用户的不同成交各自归因,窗口内触点可被多笔成交复用;导入按主键幂等(`INSERT OR REPLACE`),重复导入同一成交不累加。
- 撤销成交(`reversed=true`)净额归零;部分退款后按原归因权重分摊净额。
- 金额以**分**为单位;线性分摊用最大余数法,余数按小数余数降序、再按触点编号升序分配,渠道合计恒等于成交净额(含负净额)。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/import/{touchpoints\|identity_bindings\|conversions\|refunds}` | 幂等导入 JSON 数组 |
| POST | `/api/seed` / `/api/reset` | 载入演示数据 / 清空 |
| GET | `/api/summary?model=&lookback_days=` | 渠道汇总 |
| GET | `/api/conversions?model=&lookback_days=` | 成交列表(含每笔渠道分摊) |
| GET | `/api/conversions/{order_id}?model=&lookback_days=` | 成交路径与分摊明细(含被排除触点及原因) |
| GET | `/api/compare?lookback_days=` | 三种口径下每笔成交的渠道分摊对比 |

## 演示数据覆盖的场景

| 订单 | 场景 |
|---|---|
| O1 | 跨日触点:小红书触点在 7 天窗口外、30 天窗口内,首次触达随窗口变化 |
| O2a / O2b | 成交后才建立的身份绑定:O2a 归未知来源,O2b 可见朋友圈广告 |
| O3 | 三方平分 1 分钱:余数相同按触点编号,小红书得 1 分 |
| O4 | 部分退款 4000 分,净额 6000 按权重分摊 |
| O5 | 撤销成交,净额归零 |
| O6 | 同一时刻两个触点,按编号 12 < 13 排序 |
| O7 | 完全无触点 → 未知来源 |
| O8 | 仅直接访问,末次非直接回退到直接访问 |
